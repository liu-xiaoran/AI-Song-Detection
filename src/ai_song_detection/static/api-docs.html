LOCAL API REFERENCE

Build on the detector.

Analyze an audio file or check the service from your own tools. This reference and its request console run without external assets.

This service has no authentication and is intended for local use. The examples address the server you are currently viewing. Only one analysis request can run at a time.
POST

/api/v1/detect

Analyze one audio file. Send multipart/form-data with a single file field named file. Uploaded audio is stored temporarily on this server and deleted after processing.

Input limits

  • Maximum file size: 100 MB (104,857,600 bytes).
  • Minimum audio duration: 10 seconds.
  • Default: first 300 seconds. Query options: start_seconds ≥ 0 and duration_seconds 10–300.
  • Supported extensions: MP3, WAV, FLAC, M4A, AAC, OGG, OPUS, AIFF, AIF, WMA. Decoding support depends on the installed audio tools.

Example request

curl -X POST http://127.0.0.1:8000/api/v1/detect \
  -F "file=@song.mp3"

Replace the example host and port if your service uses a different address. Let your HTTP client set the multipart boundary.

POST

/api/v1/jobs

Queue one multipart file with the same window query options. Returns HTTP 202 with id, status, stage, created_at, updated_at, result, error. One job runs at a time; up to eight others can wait or upload. At capacity the server returns 429.

Poll GET /api/v1/jobs/{id}. Cancel with POST /api/v1/jobs/{id}/cancel. Status is queued, running, cancelling, completed, failed or cancelled. Cancelling waits for the worker to end; only cancelled is terminal. Stages name hashing, decoding, preprocessing and inference rather than a guessed percentage.

Completed results follow the contract above. Errors use {code, message}. Reports live in memory for one hour and at most 100 terminal jobs; restart clears them. Unknown or expired IDs return 404. Temporary audio is removed when work ends.

GET

/health

Check readiness. HTTP 200 indicates the model and audio tools are available. HTTP 503 indicates degraded readiness. The JSON includes status, version, model_loaded, and ffmpeg_available.

Error responses

Application errors use {"detail": {"code": "…", "message": "…"}}; invalid query parameters use the framework HTTP 422 validation list. Read the code for programmatic handling and the message for a readable explanation.
