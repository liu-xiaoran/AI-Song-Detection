# Product Scope

## Purpose

Provide a fast and affordable way to assess whether a song contains AI-generated audio. The accuracy target is 99%, subject to the evaluation protocol in [Evaluation Plan](evaluation.md).

## Initial scope

- Accept an individual audio file for song-level analysis.
- Validate decodability, duration, and supported audio properties before inference.
- Analyze audio content rather than relying on filenames, tags, or claimed provenance as prediction shortcuts.
- Produce one of three assessments: `likely_ai_generated`, `likely_human_created`, or `uncertain`.
- Record the detector version and the audio coverage used for each assessment.
- Measure end-to-end processing time and cost per song.

These are implementation requirements; the current repository does not provide this functionality yet.

## Reference labels

| Label | Meaning |
| --- | --- |
| Fully AI-generated | The musical audio was generated by an AI system. |
| Human-created | The recording has documented human production provenance and no known generative audio contribution. |
| Mixed | The recording combines generated and human-created audio, such as generated vocals over human accompaniment. |
| Unknown | The available provenance is insufficient to assign a reliable reference label. |

Begin binary accuracy evaluation with fully AI-generated and human-created recordings. Report mixed and unknown recordings separately until a validated policy supports them. Reference labels describe dataset provenance; prediction outcomes describe the detector's assessment.

## Result requirements

A future result should include:

- The song-level assessment.
- A model score with a documented meaning; display it as a probability only after calibration has been validated.
- Model and decision-threshold versions.
- Analyzed duration and coverage of the song.
- Processing time and reasons for uncertainty or unsupported input.

Invalid or unsupported input must produce an explicit error, rather than a human-created assessment. Low-quality, short, heavily modified, or unfamiliar audio may require an uncertain assessment.

## Decisions to make before implementation

- Baseline model, license, inference requirements, and permitted commercial use.
- Supported audio formats, duration limits, and input size limits.
- Full-song versus sampled-segment analysis and aggregation strategy.
- Deployment hardware, concurrency, latency target, and cost budget.
- Score thresholds and acceptable false-positive and false-negative rates.
- Audio retention, deletion, and any permitted use for training.

## Data handling

Use only audio and models with appropriate permissions for their intended use. Keep private audio and credentials out of the repository. Define retention and deletion behavior before introducing an upload service. Training use of submitted audio requires a separately defined permission policy.
